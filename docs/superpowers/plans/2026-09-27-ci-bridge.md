# The CI bridge (epic memql#5476) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut the Go-touching pull-request loop by sharding `go-tests` and `db-tests` from a checked-in timing table, running the seven node-tag passes as a gated matrix, taking CodeQL off the pull-request path, making the npm and Go caches actually hit, and turning the ruleset's strict up-to-date rule off.

**Architecture:** A new `plan` job runs `go run ./scripts/ci/affected plan`, a thin CLI over a pure library, `scripts/ci/selection`. The library builds the union import graph from `go list -e -json` across the default build and every node tag, maps a pull request's changed files onto packages, closes over reverse test-binary dependencies, and partitions the selected packages into budget classes and shards (longest-processing-time first). Its output (a JSON matrix per lane, a tag-pass flag, a module list) drives `go-tests`, `db-tests`, `go-tests-tags` and `module-boundaries`. Push and merge_group runs plan in full mode.

**Tech Stack:** Go 1.27.1 (stdlib + `gopkg.in/yaml.v3`, already a root-module dependency), GitHub Actions (SHA-pinned actions already in the tree), bash.

**Spec:** `docs/superpowers/specs/2026-09-16-pipelines-program-design.md`, section 4 epic 1, section 5 (failure modes), section 6 (testing). Issues #5481, #5482, #5483, #5484, #5485.

## Global Constraints

- ONE pull request from `epic/ci-bridge` closes #5481-#5485 (the owner's instruction for this session overrides the epic body's "Ships in 2 PRs").
- Push and merge_group runs stay unconditional: the planner emits the full set for any event other than `pull_request`.
- `ci-required` stays the single required check and needs every lane, including every shard (a matrix job's result aggregates its entries).
- No `-run` partitioning, no retry around a test, no raised per-package budget: component/memql 600s serial, component/packages 300s, the other db-gated packages 180s, the root package 300s uncached, the rest 600s.
- Go 1.27.1, every action pinned by the SHA already used in the tree.
- Stage by explicit path; never `git add -A`. Regenerate the architecture model last.
- No emojis anywhere.

## Measured baseline (2026-09-27, the last seven green push runs on main)

| lane | wall clock | what dominates |
|---|---|---|
| db-tests | 21.7-24.2 min | component/memql step 696s (the package alone 496s), fast step 516s |
| go-tests | 18.0-19.9 min | complement 707s (cmd/memqllint 446s, cmd/memql-lsp 346s, test/conformance 283s), root 215s, seven tag passes 250s |
| go-checks | 9.8-10.3 min | bounded fuzz 365s, go build 137s |

Every `setup-go` cache in the repository is 22 MB: whichever Go job finishes first (path-routing) saves the key and every other lane restores almost nothing, so no job has ever had a warm build or module cache. The repository's cache store is at 10.09 GB against a 10 GB limit, mostly CodeQL's per-pull-request `codeql-dependencies` caches (about 1 GB each). A cold module build here fills 1.45 GB of build cache and downloads 941 MB of modules; warm, it rebuilds in 13s.

Affected selection, prototyped over the last 25 merged pull requests: 11 were full runs anyway (a go.mod/go.sum or workflow change), and in all 14 others every heavy package (component/memql, cmd/memqllint, cmd/memql-lsp, test/conformance, the root) was in the affected set, because they sit downstream of nearly everything. Sharding is where the time comes back; the design record's "3-4 minute small change" does not hold on this import graph and the ci-design record must say so.

## Review Focus

1. A push or merge_group plan that emits an empty or partial matrix: the shard lane would skip and `ci-required` would read green over nothing. Pinned by full-mode floors in `MakePlan`, the union-equals-input check in `Partition`, and job `if:`s that start `github.event_name != 'pull_request' ||` so an empty matrix is an error, not a skip.
2. A changed file the graph cannot place (a deleted file, a file only a node tag compiles, testdata, a deleted package directory): it must land on a package, never vanish. Pinned by `Select` fixture cases.
3. A pull request whose diff cannot be computed (base commit absent, shallow history): an empty change list must mean FULL, never "nothing changed". Pinned by `MakePlan` and `Select` cases.
4. The db selector gate disarmed by the dynamic matrix: cidb must derive the selector from the canonical set when the step reads `${{matrix.packages}}`, refuse a step that mixes literal packages with it, and a live test must prove the real planner in full mode covers every provisioned package.
5. The shared Go cache poisoned or thrashed: exactly one writer (go-checks), only on a push to main, and every Go job restores through the one composite action. Pinned by a static guard in scripts/dev.

Rules `Select` implements, each a fixture case:
1. empty change list -> full; a path that is absolute or climbs out -> full;
2. any `go.mod`/`go.sum`/`go.work`/`go.work.sum`, anything under `.github/`, `Makefile`, the selector's own sources, `scripts/ci/db-gated-packages.sh` -> full, naming the file;
3. a file some package names (Go source under any build configuration, an ignored file, an embed match) -> that package;
4. otherwise the package owning the nearest ancestor directory (testdata, a deleted file, a file in a deleted package directory -- the root is a package, so every path has one);
5. any non-Go file adds the gate patterns (the packages whose tests read repository files by path);
6. affected = seeds plus every package whose test-binary deps contain a seed (deps are transitive, so one level);
7. `TagChange` when a changed file is in some package's `TaggedFiles`.

**Interfaces (produced):**

```go
type Class struct { Lane, Name string; Trees []string; Timeout string; Serial, Uncached bool; Shards int }
func ParseClasses(text string) ([]Class, error) // columns: lane class trees timeout mode shards
type Shard struct {
	Name, Packages, Timeout string // JSON: name, packages, timeout
	Parallel int; Uncached bool    // JSON: parallel, uncached
	Class string; Dirs, Unknown []string; Seconds float64 // not serialised
}
func Partition(lane string, dirs []string, classes []Class, seconds map[string]float64, cpus int) ([]Shard, error)
type Timings map[string]map[string]float64 // lane -> dir -> seconds
func ReadTimings(r io.Reader) (Timings, error)
func (t Timings) Write(w io.Writer, header []string) error
func ParseGoTestOutput(r io.Reader, prefix string) (map[string][]float64, error)
func (t Timings) Merge(lane string, samples map[string][]float64)
```

Partition: a package belongs to the first class with a tree containing it (tree `.` is the root package only), else the lane's default class; per class, n = min(Shards, packages); longest-processing-time first over measured seconds (ties by name), then each unmeasured package, by name, to the then-lightest shard at a nominal 5s; shard names `<class>` or `<class>-<i>`; union must equal input exactly (refuse otherwise); Serial -> parallel 1, else cpus.
