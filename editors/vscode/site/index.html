One file.
Four useful building blocks.

A personal reading list: define a record, add an item, read your list, and expose the query as a tool. No model call required.

Interactive code example.
This page does not execute MemQL.

reading.memql 
@namespace("reading")
@rowAuthz(owner="ownerUserId")
@displayCard(primary="title", status="finished")
concept readingItem {
  ownerUserId  string!
  title        string!
  finished     bool
}

Declare the shape of a reading item and its ownership tier. The engine supplies intrinsic fields such as id.

Download the complete .memql file Download its language manifest
Run this example in VS Code
  1. Download both files into a new folder. Open it in VS Code with the MemQL extension installed.
  2. To validate offline from the repository, run go run ./cmd/memqllint examples/reading-list/reading.memql. Use your own file's path for the downloaded copy.
  3. Connect a trusted workspace to a development cluster. Sign in with an account allowed to author constructs.
  4. Dry-run and promote readingItem using its training action. Concepts cannot be privately staged. The schema is shared; its rows have the declared ownership tier.
  5. Run addReadingItem from CodeLens. Give it a fresh itemId and a title. This writes a real row.
  6. Run readingItems with finished: false to see the item. The tool listReadingItems calls that same query.

Running local definitions uses the editor's authoring session; it does not automatically promote them. To retain supported queries or tools beyond the session, explicitly stage or promote them. Read about training and scope.

for MemQL.

Build the extension from the repository and install it into your editor. Your first file can stay entirely local.

VS Code 1.91+ · Node.js 20+ · Go toolchain from go.mod · npm · Git · Make · unzip

Read the installation guide

  1. Clone and install

    git clone https://github.com/znasllc-io/memql.git
cd memql
make vscode-install

    Builds for your host and installs through the code CLI. Replaces an existing local MemQL extension.

  2. Reload VS Code

    Run Developer: Reload Window, then open a folder of .memql files.

  3. Connect when you need the engine

    Use MemQL: Add Cluster and sign in. Local cluster installation supports Linux x64 and Apple Silicon macOS, with Docker running.

Want only the archive? Run make vscode-package. The script prints the VSIX path. Public registry availability is not assumed here.
